Diagnosis: `/api/state` paints pane status on **every** card in a role's lane, not on the one being worked. `tasks` maps each board row through `task-with-status`. That function takes the card's `:lane`, samples that role's tmux pane, and runs `im-status`, which stores one sentence **per role** (`pane-status`). The dashboard copies `task.status` onto each card with no "waiting in queue" fallback. Tests only create one specifier card, so the copy-to-all-cards behavior was never seen. Active is the in-process `task:` (or the injected New Task still in the master lane). Other cards in that lane wait.
